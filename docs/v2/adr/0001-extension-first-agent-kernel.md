# ADR 0001: 采用扩展优先的领域无关 Agent Kernel

- 状态：Accepted
- 日期：2026-08-19
- 决策者：项目维护者
- 替代：无
- 被替代：无

## 上下文

当前项目已经具备轴承需求解析、COMSOL 代码生成、运行与 Web 展示能力，但业务规则、修复经验和执行路径容易逐渐耦合到单一流程。V2 需要支持更多轴承类型和工程领域，并允许增加或撤销 Skill、Function、MCP 工具、修复规则、确定性路径和记忆适配器，而不持续修改核心调度代码。

## 候选方案

1. 继续扩展单体 Agent，通过条件分支覆盖新领域和新错误。
2. 为每类轴承维护独立 Agent，复制公共的规划、执行和恢复逻辑。
3. 建立领域无关 Kernel，通过带版本的扩展清单和注册表装配能力。

## 决策

采用方案 3。

Kernel 只负责状态机、上下文预算、能力选择、策略执行、观测记录和终止条件。轴承参数、COMSOL API 规则、修复规则、模板和验收约束由扩展提供。扩展必须具备稳定标识、版本、依赖、输入输出契约、权限声明、启停状态和测试证据。

确定性路径优先于开放式代码生成；生成式步骤只能在契约、沙箱、测试和有界修复循环内运行。任何跨阶段对象必须采用结构化契约，不能依赖自然语言文本作为唯一接口。

## 后果

正面影响：

- 新能力可以独立开发、测试、启停和回滚。
- Kernel 的回归面更小，轴承领域知识可以复用并演进。
- RAG、MCP、Skill 和修复策略拥有统一装配边界。

成本与风险：

- 初期需要设计注册表、清单校验和兼容策略。
- 扩展粒度过细可能增加选择成本，粒度过粗则重新形成耦合。
- 动态加载不能绕过权限、沙箱和验收门禁。

## 验证

- Kernel 包不得导入轴承领域实现模块。
- 至少一个扩展能仅通过注册表启停，并通过契约测试。
- 缺失依赖、版本冲突和重复能力标识必须在执行前失败。
- 删除某个非必需扩展后，Kernel 基础测试仍应通过。
